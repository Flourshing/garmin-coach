# 常驻部署

目标是让微信接收、佳明查询和分析在个人电脑关机后仍能运行。当前已准备容器文件和源码打包工具；本机验证成功不等于镜像已构建或云端已部署。

## 运行要求

- 不休眠的常驻进程和可持久保存的磁盘。
- 可连接佳明中国区、微信服务和所选模型服务。
- HTTPS 公网入口、明确的网关令牌和环境变量。
- 同一个微信账号只在一处接收，迁移时先停止原服务。

不要把可能休眠的网页服务当作全天候机器人。平台、地区、配额和费用由部署时实际核对，见 [费用组成](costs.md)。

## 环境变量

| 变量 | 用途 |
| --- | --- |
| `DEEPSEEK_API_KEY` | 模型密钥，运行时注入，不进入镜像 |
| `OPENCLAW_GATEWAY_TOKEN` | 随机网关令牌，必填 |
| `OPENCLAW_PUBLIC_ORIGIN` | 实际 HTTPS 域名，不使用通配符 |
| `PORT` | 默认 8080 |
| `GARMIN_DATA_DIR` | `/data/garmin` |
| `OPENCLAW_STATE_DIR` | `/data/openclaw` |
| `OPENCLAW_WORKSPACE_DIR` | `/data/coach-workspace` |

将持久卷挂到 `/data`。佳明令牌、微信授权、工作区偏好、记忆和缓存都依赖这些目录；容器重建不能丢失它们。

## 构建与检查

在项目根目录可执行：

```text
docker build -t garmin-coach .
```

Dockerfile 固定 OpenClaw 运行时清单，复制明确的程序文件及教练模板。`.dockerignore` 默认拒绝所有内容，仅允许构建所需文件。该命令需要本机已安装 Docker；文档中的命令不代表当前环境已完成镜像构建。

若向 Railway 等平台上传源码，先运行：

```text
python prepare_railway_build.py
```

脚本在 `.private/railway-build-随机值/` 生成干净的构建目录，并写入文件校验清单；它不会上传、登录或创建服务。上传时以该目录为根，不能上传整个项目私有目录。

## 首次上线

1. 配置持久卷、运行时环境变量和 HTTPS 域名，启动容器。
2. 在平台私有终端完成佳明中国区登录，使用容器中的 Python 环境运行 `collect.py --login --portal --days 1`。
3. 完成微信插件安装或检查，然后扫码绑定，确认渠道工作。
4. 检查 `/healthz` 和 `/readyz`，再在微信实际发起一次数据查询。
5. 私下迁移原工作区的 `USER.md`、`MEMORY.md` 和 `PREFERENCES.md`；重新准备配置不会覆盖它们。
6. 明确需要测试日报时再运行 `prepare_daily_job.py --run-test`，检查实际送达。正式任务默认停用，启用前核对时区、接收人和重复任务。

云端使用同一组 10 个只读数据工具和 1 个本地绘图工具和偏好规则。新增模块时同步 Dockerfile、构建白名单和测试；不要把 Windows 本机代理、密钥文件或账号快照复制到镜像。

## 验收

服务持续运行、重启后状态保留、微信真实收发、佳明数据正确、失败不误报送达、实际定时执行，以及个人电脑关机后仍可使用，都需要在部署平台上分别验证。

绘图依赖 Matplotlib；镜像安装 Noto CJK 字体供中文标签使用。PNG 与旁侧元数据保存在持久工作区 `charts/` 中，不进入镜像或 Git。微信通过回复附件发送图像，不能只返回云主机上的文件路径。
